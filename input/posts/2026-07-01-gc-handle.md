In this article I will write about two new types of GC handles that were introduced in the CoreCLR
garbage collector in the years 2024 and 2025. While they are internal implementation details of .NET,
I think they are interesting to talk about.

To summarize my 2024 post, I discussed the 10 different types of GC handles implemented in CoreCLR's garbage
collector. To summarize, the GC in CoreCLR is a
[tracing garbage collector](https://en.wikipedia.org/wiki/Tracing_garbage_collection),
which means the GC determines which objects are alive by walking the object graph, starting at static
variables and local variables[^1]. Not all code patterns fit into this model, particularly cases
involving interop with native code, so for those cases the GC handle interface exists. This facility
provides handy features for working with objects on the GC: a way to manipulate the lifetime of objects
and a way to pass around handles to GC objects that can be turned back into GC objects at a later time.
This is exposed in the .NET base class library in the
[`GCHandle` struct](https://learn.microsoft.com/dotnet/api/system.runtime.interopservices.gchandle),
the [`WeakReference` class](https://learn.microsoft.com/dotnet/api/system.weakreference),
and the [`DependentHandle` struct](https://learn.microsoft.com/dotnet/api/system.runtime.dependenthandle).
Beyond these types of publicly exposed GC handles, there are several types of handles that are crated
by the .NET runtime for it's own purposes. My previous article covered the types of handles that existed
at the start of 2024.

This article with cover two types of GC handles that have been introduced sometime between the start
of 2024 and 2026.
